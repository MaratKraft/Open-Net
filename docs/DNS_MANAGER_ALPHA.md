# DNS Manager — v0.4.0-alpha.1

Экспериментальный модуль системных настроек. Он не запускается общей кнопкой Zapret/TG, не меняет DNS при старте, выходе или автозапуске оболочки. Предыдущий Stable v0.3.2 и его опубликованные файлы не изменяются этой веткой.

## Пользовательский сценарий

DNS Manager расположен компактной строкой в категории «Системные настройки»: иконка, название, короткий статус и шестерёнка настроек. Повторное нажатие возвращает скрытое или свёрнутое окно. Ошибка чтения адаптеров или защищённой резервной записи показывается внутри окна и блокирует изменение, а не мешает открыть настройки.

Окно 560 × 680 DIP сохраняет прокрутку и закреплённые действия. Подробности профиля и проверка соединения раскрываются отдельно. Причины недоступности применения и восстановления отображаются рядом с действиями. Неприменённый профиль не даёт права на восстановление.

Статус «Системный DNS» не означает профиль Open Net, даже если найденные IP совпадают с каталогом. Название собственного профиля сохраняется в защищённом журнале и показывается только при совпадении наблюдаемой конфигурации. Старые записи без ID показывают общее имя собственного профиля. Несовпадение означает «Настройки изменены извне».

### Safe Preview

Пользовательская поставка собирается отдельно через `publish.ps1 -SafePreview`. Сам EXE всегда выбирает имитацию; CMD необязателен. Данные изолированы в `test-results/preview` рядом с EXE. Реальные DNS reader/writer, probes и Windows startup store не выбираются. Привилегированные команды, автозапуск и разработческие self-test/installer-test отклоняются до инициализации приложения. Это отличается от разработческого TestBuild, которому требуется `--test-mode`.

«Применить…» и «Восстановить…» меняют только вымышленные данные и журнал имитации, включая восстановление после перезапуска. Xbox DNS можно испытать в имитации; запрет настоящего применения сохраняется. Подтверждение явно говорит об имитации без UAC. Статус главного окна всегда «Режим просмотра».

1. Откройте «Настроить» у DNS Manager. Выберите один физический адаптер. Текущее автоматическое/ручное назначение, серверы IPv4/IPv6 и ограничения отображаются отдельно от выбора профиля.
2. Выберите ComssDNS, Xbox DNS или свой DNS. Порядок адресов сохраняется. IPv4 и IPv6 выбираются отдельно; по умолчанию IPv6 не меняется. Оставшийся IPv6 DNS может обслуживать запросы к другому провайдеру.
3. «Применить…» показывает исходное и планируемое состояние. После явного подтверждения Windows запрашивает UAC. До записи создаётся защищённая резервная запись, после каждого шага проверяется фактическая конфигурация.
4. «Проверить настройки» повторно читает конфигурацию без сетевых запросов.
5. «Восстановить…» показывает исходную конфигурацию и требует подтверждения/UAC. Возвращает ручные адреса в прежнем порядке либо прежний автоматический режим, отдельно для каждой изменённой семьи. DHCP/RA может выдать другие эффективные DNS; прежний lease не записывается как ручная настройка.

В первой альфе перед новым применением нужно восстановить предыдущую активную транзакцию. Другие адаптеры, firewall, маршруты, IPv6 как протокол, browser Secure DNS, hosts и существующие сетевые процессы не изменяются.

## Ограничения первой альфы

- Запись DNS рассчитана на Windows 10 build 19041+ и Windows 11. API/layout, настоящий UAC, поведение reset и физические ОС требуют контролируемой проверки. Успех fake-тестов не подтверждает работоспособность backend на реальном адаптере.
- VPN/виртуальные адаптеры, неизвестный исходный режим, overrides профиля сети, управляемые DNS policies, неподдержанные DDR/DoT/global modes и независимо непроверяемый IPv6 DoH доступны только для просмотра.
- Поддержано сохранение и восстановление собственных per-adapter DoH-свойств IPv4 через DNS_INTERFACE_SETTINGS3: сервер/индекс, исходный URI либо автоматический шаблон, флаги и разрешение plaintext fallback. Чтение API сверяется с настройками того же адаптера. Само наличие системного DoH-шаблона не доказывает активное шифрование. Активный DoH не отключается: выбранный поддерживаемый профиль получает свой HTTPS-шаблон с сохранением политики fallback. Подробнее: [DNS/DoH validation](DNS_DOH_VALIDATION.md).
- Нет локального DNS forwarder, установки службы, очистки DNS-кэша, принудительного DNS-перехвата или отключения IPv6.
- Custom: до четырёх IP на семью, без URL/портов, повторов, loopback, unspecified, multicast или scoped/link-local IPv6. Восстановление может вернуть ранее существовавший локальный resolver из доверенного исходника.
- Xbox DNS присутствует в каталоге, но новое применение заблокировано: на официальном сайте при проверке 12.10.2026 сообщалось о недоступности. Уже установленные настройки не меняются. Нет скрытого обновления каталога или автоматического выбора альтернативы.

Comss IPv4: `83.220.169.155`, `212.109.195.93`; IPv6 на прочитанной официальной странице не опубликован. Xbox: IPv4 `111.88.96.54`, `111.88.96.55`; IPv6 `2a00:ab00:1233:26::50`, `2a00:ab00:1233:26::51`. [Comss](https://www.comss.ru/page.php?id=7315), [Xbox](https://xbox-dns.ru/). Это опубликованные параметры, а не измерение доступности из вашей сети. Работа ChatGPT/Gemini не обещается.

## Резервная запись, конфликт и Portable

До каждой записи сохраняется durable intent. Журнал содержит GUID адаптера, хэш идентичности машины, владельца, исходные режимы/упорядоченные адреса обеих семей, ожидаемую/целевую конфигурацию, fingerprint зависимых DNS-настроек и phase/pending family. Per-adapter DoH properties IPv4 сохраняются вместе с исходным назначением, участвуют в проверке конфигурации и возвращаются при восстановлении. Перед первой записью защищённая резервная запись перечитывается и проверяется. Каталог шифрования и политики участвуют в сравнении; они никогда не редактируются.

Авторитетное хранилище: `%ProgramData%\Open Net DNS Recovery\<SID>`. Владелец и права записи — Administrators/SYSTEM; соответствующий пользователь имеет только чтение. Приложение проверяет ACL и отсутствие reparse paths. Имеющий произвольные права администратора процесс находится вне этой границы защиты.

В `Data\Dns\Backups` после операции создаётся пользовательская копия. Она не служит инструкцией привилегированному помощнику. Данные копий/журналов приватны: не публикуйте их без удаления имён адаптеров/адресов. В Git, PR и сборки они не включаются.

При запуске оболочка просматривает собственные записи восстановления и читает конфигурацию только адаптеров с активной собственной записью для правдивого статуса. Проверка соединения при этом не запускается. Она ничего не применяет автоматически. После выбора адаптера сравнивает текущую конфигурацию с подтверждённо применённой или сохранённым pending intent. При постороннем изменении запрещает восстановление. При неоднозначном частичном результате также не выполняет запись наугад. Пользователь видит сохранённую конфигурацию и может разобрать ситуацию вручную.

Для Portable защищённая запись остаётся на исходной машине, даже если папка EXE перемещена или потеряна. Новый экземпляр Open Net того же пользователя может открыть DNS Manager для восстановления без запуска Zapret/TG. Перенос папки на другой компьютер не переносит право восстановить там конфигурацию исходной машины. Отдельная произвольная команда импорта backup не поддерживается.

## Windows backend и UAC

Локальное чтение использует NetworkInterface, GetInterfaceDnsSettings и read-only inspection registry для различения статического NameServer и эффективного DHCP/RA списка. Несогласованность данных закрывает Apply. Реальная запись ручного списка — SetInterfaceDnsSettings с одним NameServer flag и явно выбранной семьёй; другие поля не устанавливаются. Исходный автоматический режим возвращается фиксированной командой системного netsh для одного index, заново полученного по GUID; validate/network probes не включаются. Поведение команды на Windows 10/11 остаётся release gate.

Операции помощника ограничены Apply/Restore; неизвестная операция не исполняется. Проверяются токен, живой родительский процесс, executable/start identity, SID родителя, утверждённый fingerprint и актуальные ограничения. SHA-256 утверждённого payload передаётся в фиксированных аргументах UAC и сравнивается с однократно прочитанными байтами запроса: изменение пользовательского request.json не изменяет подтверждённый план. Одноразовый токен отмечается в защищённом machine-local хранилище, чтобы удаление пользовательского response.json не разрешало повтор запроса. Операции одного адаптера сериализуются. Privileged restore читает только защищённый журнал, а не переданный пользователем исходник. Не предоставляется shell/произвольный executable/argv API. TestBuild отвергает `--dns-elevated` целиком.

Исходники: [GetInterfaceDnsSettings](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getinterfacednssettings), [SetInterfaceDnsSettings](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-setinterfacednssettings), [DNS_INTERFACE_SETTINGS3](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-dns_interface_settings3). Автоматический DNS и статический override должны различаться независимо от DHCP-настройки IP.

## Проверка соединения

Запускается только отдельной кнопкой после подтверждения конкретного endpoint. Доступны example.com, chatgpt.com и gemini.google.com: системное разрешение имени и HTTPS HEAD без cookies/авторизации, со штатной проверкой сертификата, ограниченным временем, без переходов по redirects и без загрузки тела ответа.

Проверка не привязана к выбранному адаптеру, учитывает системный resolver/cache/proxy. DNS и HTTPS показываются раздельно; HTTP 403/429 или страница входа не объявляются работающим аккаунтом. Функциональную доступность сервиса проверяет пользователь вручную. Автоматические тесты используют fake DNS/HTTP и никогда не вызывают реальные probes.

## Проверки и следующий этап

Изолированная логика покрывает ручной/автоматический режим, порядок, независимость семейств, malformed input, смену baseline, journal failures на apply/restore границах, частичное применение, повторный apply, смену DNS/DoH извне, идентичность машины/адаптера, restart/corrupt record, запрет реального helper в safe mode и раздельный UI/process lifecycle. Интерактивный safe harness проверяет отмену, fake apply/restore и темы; rendered scales не заменяют физический DPI.

До настоящего опыта: отдельно согласовать выбранный адаптер/семью и точный diff; сохранить read-only baseline; показать доступное восстановление и ручную процедуру Windows; проверить защищённый журнал и права. Не отключать Zapret/TG. Если per-adapter DoH IPv4 подтверждён Windows API и параметры поддерживаются, план допускается с сохранением шифрования. Настоящее применение всё равно требует отдельного согласования и подтверждения/UAC.

Ветка и Draft PR — экспериментальная разработка. Merge в main и GitHub Pre-release допускаются только после отдельного подтверждения владельца; Pre-release не заменяет Stable Latest.
