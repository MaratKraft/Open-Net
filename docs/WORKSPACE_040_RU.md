# Open Net 0.4.0 Alpha: рабочая область и DNS

Разработка ведётся в Draft PR №2, поверх стабильной v0.3.3. VPN не включён. Реальные изменения сети требуют отдельного согласия.

## Рабочая область

«Модули…» управляет видимостью Zapret, TG WS Proxy и DNS Manager. Установка, видимость, участие в общей группе, фактическая работа и запуск с Windows независимы. При миграции прежний набор автозапуска фиксируется отдельно от галочек группы. DNS не применяется автоматически при входе в Windows.

Скрытие активного инструмента требует подтверждения и оставляет его работать. Ссылка «Скрыто активных» открывает управление модулями. Групповое действие со скрытыми участниками отдельно показывает их имена. Сброс расположения возвращает порядок и видимость, не меняя процессы, DNS, назначение кнопки и автозапуск.

Главная кнопка изначально управляет группой. Её подпись позволяет назначить Zapret, TG WS Proxy или DNS. Назначение сохраняется независимо от порядка. Скрытая/недоступная цель не заменяется другой. Для отсутствующего движка открываются настройки установки.

«Изменить порядок…» открывает отдельный режим. Перетаскивайте за ручку или используйте кнопки вверх/вниз и Alt+↑/↓. Сетевые действия строк скрыты; «Готово» сохраняет порядок, Escape отменяет. Порядок отображения не задаёт порядок запуска.

Профиль расположен перед прежним блоком обновления/настроек/галочки. Выбор не запускает инструмент. Работающий Zapret сохраняет новую стратегию как ожидающую; отдельное действие перезапуска либо последующий явный запуск применяет её. TG не получает фиктивного профиля. Для встроенного DNS обновление перечитывает настройки Windows.

Автоматическая высота для одного/двух/трёх модулей — примерно 510/583/656 DIP, верхняя граница 780 и рабочая область монитора. После ручного изменения высота сохраняется; «Высота по составу модулей» возвращает Auto. Профиль и статус не перерасчитывают высоту. На маленьком экране уменьшается верхняя область, прокручивается список, нижние настройки остаются отдельно. Положение сохраняется и ограничивается рабочей областью.

## DNS Manager

Основное окно: адаптер, профиль, адреса, фактический статус и кнопка «Включить»/«Выключить». Остальные функции находятся в «Дополнительное»: пользовательский профиль, DoH, IPv6, диагностика, исходная конфигурация, повторное применение, автоматический DNS и очистка кэша.

Включение использует существующие подтверждение, UAC, защищённый исходник и проверку чтением после записи. Выключение восстанавливает этот исходник: ручные адреса и DoH либо автоматический режим, если он был первоначальным. Открытие окна, обновление, выбор профиля и перестановка DNS не меняют Windows. Очистка кэша по умолчанию отключена; повторное применение всегда исключает её.

Статус определяется снимком адаптера и управляемым журналом, проверяется повторно при открытии и обновляется во время работы. Совпадение адресов с профилем без подтверждённой сессии не означает, что профиль применён Open Net. Приложение не отменяет DNS при закрытии. После повторного запуска управляемый статус восстанавливается только после чтения фактической конфигурации. Сторонние изменения не считаются нашим успешным применением.

При старой сессии или стороннем изменении появляется «Разобраться…». Можно подтвердить использование текущих настроек как нового исходника. Полностью прочитанный снимок проверяется повторно, старый журнал архивируется и проверяется, новый исходник сохраняется и перечитывается. Эта операция сама не записывает DNS. При ошибке архивирования исходный журнал остаётся действующим. Неизвестные режимы/политики/неподдерживаемое шифрование не обходятся этой командой.

Архивы защищённых журналов сохраняются в `Archives` рядом с текущей машинной записью восстановления. Они не используются автоматически вместо текущего исходника. Обычное повторное применение продолжает сессию и сохраняет первый Before. Новая сессия после завершённой также архивирует прежний защищённый журнал. Пользовательские копии в Data остаются информационными. Автономный запуск восстановления: `Open Net.exe --dns-recovery`; см. DNS_RECOVERY_RU.txt. Он использует текущую защищённую запись; старые архивы предназначены для отдельного разбора, а не автоматической подмены исходника.

## Проверки и границы

Изолированные проверки включают миграцию и сохранение настроек, независимость запуска с Windows, порядок, высоту, геометрию иконок, темы, материалы, трей, DNS-транзакции и ошибки. Новые сценарии проверяют архивирование и отказ диска, нулевую DNS-запись при принятии исходника, закрытие/повторное открытие окна, стороннее изменение mock-адаптера и восстановление принятого Google DNS вместо старого исходника.

Safe Preview всегда работает с отдельным mock-адаптером и имитационным журналом. В нём запрещены привилегированные DNS и startup entry points. Автоматические проверки не запускают настоящие сетевые инструменты. Физические переходы между мониторами с разным DPI, реальная перезагрузка и реальная запись DNS не заменяются отрисовкой/сериализацией и требуют личного испытания. Доступность ChatGPT/Gemini не гарантируется результатом записи DNS.

## Личная проверка

1. Начать с Safe Preview. Проверить состав из одного, двух и трёх модулей, порядок мышью/клавиатурой, отмену Escape и повторный запуск.
2. Изменить высоту, перезапустить, изменить состав; ручная высота должна сохраниться. Затем вернуть Auto. Проверить рабочую область и 100/125/150% на доступных мониторах.
3. Назначить главную кнопку модулю, скрыть его и переставить остальные. Не должно быть действия с другой целью.
4. В имитации включить Comss, закрыть окно DNS, открыть снова и выключить. Проверить возврат прежних значений. Сценарии ошибок находятся в дополнительной диагностике.
5. В отдельной Portable-копии проверить темы, профили, доступ к настройкам и отсутствие конфликтов данных с Standard. Сначала не регистрировать автозапуск новой копии поверх рабочей установки.
6. Перед настоящим испытанием открыть обычную сборку только для просмотра, проверить адаптер, текущие DNS/DoH и резервную запись. Подготовить доступный автономный EXE восстановления. Согласовать точный план и только затем применять/восстанавливать.

Не включать реальные DNS-действия, очистку системного кэша, новую регистрацию автозапуска или перезагрузку ради проверки внешнего вида.
