# Open Net 0.3.3 — запуск вместе с Windows

## Включение

В главном окне выберите Zapret, TG WS Proxy или оба инструмента. Выбор сохраняется
сразу; ALT-стратегия и настройки TG остаются прежними. Установите модули заранее.

В общих настройках доступны:

- «Запускать с Windows» — регистрация запуска оболочки после входа пользователя.
- «Автоматически запускать выбранные инструменты» — отдельное явное разрешение.
- «При входе в Windows запускать в трее» — включено по умолчанию; ручной запуск
  по-прежнему открывает окно.

Нажмите «Сохранить». При первом разрешении автозапуска инструментов Open Net
показывает отдельное подтверждение и штатный запрос UAC для регистрации задачи.
Нужна та же учётная запись Windows с административными правами; другой аккаунт
администратора в UAC не принимается. Пароли не сохраняются.

Только оболочка использует прежний HKCU Run. При разрешённых инструментах запись
заменяется одной видимой задачей `OpenNet.Startup.<SID>.<installation>` в Планировщике.
Задача привязана к входу этого пользователя, использует InteractiveToken и
HighestAvailable. **Open Net и запущенные им инструменты работают с повышенными
правами**. Храните EXE, данные и модули в доверенной папке. Это осознанный компромисс
v0.3.3; отдельная привилегированная служба не устанавливается.

После входа задача ждёт 8 секунд, оболочка даёт ещё 5 секунд на готовность системы,
затем один раз проверяет и запускает выбранные установленные инструменты.
Подключение к Интернету не является условием. Скачиваний и бесконечных повторов нет.
TG обрабатывается первым; отказ одного инструмента не мешает попытке другого.
Работающие и внешние экземпляры сохраняются. Неопределённый процесс не дублируется.
Ошибки доступны в главном окне, настройках модуля и журнале.

Главное окно Open Net при включённом запуске в трей не показывается и не получает
фокус. Windows самостоятельно определяет положение значка среди скрытых значков.
Трей TG и его собственные настройки остаются под управлением исходного приложения.

## Отключение и Portable

Отключите автозапуск инструментов и сохраните: задача удаляется через UAC, при
сохранённой первой опции остаётся только Run для оболочки. Отключение «Запускать
с Windows» удаляет подтверждённую регистрацию этой установки. Уже работающие
инструменты не завершаются автоматически; используйте «Остановить» в Open Net.

Portable хранит постоянный идентификатор регистрации в Data. После переноса
откройте приложение вручную: оно покажет предупреждение и предложит исправление
пути. Переносите всю папку с Data и portable.flag. Копия, пока исходный EXE ещё
существует, не может перехватить его регистрацию. До переноса лучше выключить
автозапуск и включить его заново на новом месте. Повреждённые, чужие или дублирующиеся
регистрации блокируют автоматическое изменение; журнал объясняет причину.

Обновление с v0.3.2 и импорт настроек не включают автозапуск инструментов неожиданно.
В новой установке обычные подтверждения запуска и остановки выключены. Сохранённый
выбор пользователя сохраняется; старые профили без этого поля сохраняют прежнее
поведение. UAC, отдельное разрешение автозапуска и защита принудительной остановки TG
действуют независимо от этого переключателя.
Регистрация меняется только при сохранении или явном исправлении, а не при обычном
открытии программы. Новая сборка продолжает использовать существующий single-instance
механизм и NotifyIcon, включая восстановление значка при TaskbarCreated.

## Отдельное настоящее испытание после входа

Эти действия выполняет пользователь после согласования; разработческие тесты
не создают настоящую задачу и не запускают сетевые инструменты.

1. Сохраните документы. Распакуйте тестовую Standard/Portable в постоянную папку.
   Проверьте пути модулей, ALT-стратегию и выбранные инструменты.
2. Включите три опции выше, сохраните, подтвердите согласие и UAC. При отказе
   проверьте: ваш выбор сохранён, но регистрация не объявлена готовой; прежняя
   запись Windows не должна изменяться.
3. Проверьте в Планировщике: одна задача этой установки, один EXE с `--autostart`,
   только вход вашего пользователя, без пароля, без сети как условия. Старой Run
   записи этой установки одновременно быть не должно.
4. Завершите испытательные/ручные экземпляры инструментов штатно, если хотите
   проверить именно новый запуск. Действующие внешние процессы Open Net не убивает.
5. После отдельного решения выйдите и войдите в Windows либо перезагрузитесь.
   Не позднее готовности системы и задержки проверьте значок Open Net, отсутствие
   его главного окна и CMD, состояние выбранных инструментов. Их наличие ещё не
   доказывает доступность сайтов.
6. Откройте Open Net из трея, проверьте журнал и PID. Повторный ручной запуск EXE
   должен открыть ту же оболочку без новых инструментов. Проверьте остановку
   собственных процессов через приложение.
7. Отдельно повторите с одним инструментом, затем с обоими. Восстановите свои
   настройки. Отключите автозапуск и убедитесь, что удалена только его регистрация.
8. Для Portable повторите исправление после переноса целой папки. Не переименовывайте
   или удаляйте рабочие EXE, пока они запущены.

Инструкции по Task Scheduler опираются на штатные API Windows:
[вход пользователя](https://learn.microsoft.com/en-us/windows/win32/taskschd/starting-an-executable-when-a-user-logs-on),
[RegisterTask и InteractiveToken](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskfolder-registertask).
Живой UAC, регистрация/удаление настоящей задачи, вход в Windows, работа сетевых
инструментов и физическая Windows 10 требуют этого отдельного испытания. Проверка
XML с TASK_VALIDATE_ONLY подтверждает схему, а не весь сценарий после входа.
