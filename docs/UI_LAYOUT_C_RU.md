# Open Net 0.4.0 Alpha — компоновка C и согласование вторичных окон

Дата: 25.10.2026. Ветка: feature/dns-manager-0.4.0-alpha. Существующий Draft PR №2.

## Реализовано

- Две строки модуля: название и прежние правые действия сверху, фактический статус и нейтральный профиль снизу. Плашки и разделители строк убраны. TG не получил фиктивный профиль.
- Правые области 28 DIP, промежутки 4 DIP, исходные иконки, темы и шрифты сохранены. Профиль не перемещает действия. Длинные названия сокращаются; полные активное и выбранное значения доступны при наведении.
- Активная стратегия Zapret сохраняется в записи принадлежащего приложению процесса. Выбор ALT2 при запущенном ALT13 показывает «ALT13 → ALT2» без перезапуска. Старую запись без названия стратегии приложение показывает как неизвестный активный профиль, а не угадывает по выбранному значению.
- DNS-строка строится по фактическому снимку и журналу. Совпадение адресов с Comss само по себе не даёт статус «Запущен». Изменение извне и незавершённая сессия требуют проверки. Цвет статуса независим от нейтрального профиля.
- Нижние входы «Настройки» и «Модули» стали компактными серыми действиями без постоянной заливки; мягкий hover и клавиатурный focus сохранены.
- Высота рассчитывается по измеренному содержимому. После первоначальной раскладки выполняется уточняющее измерение. Высота строк и однострочная область уведомлений фиксированы; смена статуса не увеличивает окно. Ручной размер сохраняется. Скролл при намеренно малой высоте остаётся в отдельном желобе.
- PID и технические сообщения запуска доступны в подсказках, настройках инструмента и журнале. Обычные успешные уведомления кратковременны. Ошибки и неопределённый результат не выдаются за успешный запуск.

## Нижние панели

Общая геометрия: отступы 24 / 12 / 24 / 20 DIP, высота действий 36 DIP, минимальная ширина завершающего действия 136 DIP. «Сохранить» у Zapret/TG и «Готово» в дополнительных параметрах DNS закреплены вне прокрутки. Общие настройки и «Модули» сохраняют закреплённые панели, приведённые к той же геометрии. В основном DNS сохранена одна широкая кнопка питания. Смысл «Сохранить» и «Готово» не изменён; версия приложения остаётся внизу общих настроек.

## Визуальное предложение, ещё не внедрено

Подготовлены реальные WPF-сравнения: главное окно с активными и ожидающими профилями, Zapret, TG WS Proxy, DNS, «Модули», общие настройки и раскрытые локальные подробности. Иллюстративные состояния в макетах демонстрационные; приложение проверено с собственными безопасными тестовыми процессами.

Предложение: в Zapret оставить стратегию и проверку обновлений; пути, импорт, откат и служебное меню сгруппировать в «Версия и файлы», процесс и журнал — в «Диагностика». В TG оставить состояние и обновление, те же две локальные секции. В DNS оставить адаптер, профиль, краткий статус исходника и питание; параметры/DoH/IPv6, диагностику, повторное применение и восстановление открывать из локальных подробностей. В «Модулях» сохранить строки и независимые колонки отображения/автозапуска; сброс перенести в «Ещё». В общих настройках оставить согласованные поля и группу поведения; утилитарные действия предложено собрать в «Ещё», версию сохранить снизу.

В интерактивном макете раскрытия и перестановка работают локально; кнопки обновления, выбора пути, сохранения и питания не выполняют системных операций. Пример раскрытия показывает, что функции сохраняются. Глобального переключателя режимов нет. Предложенные группировки требуют согласования; финальные Standard/Portable/Safe Preview для пользователя подготавливаются после него.

## План реального испытания — требуется отдельное разрешение

1. Снять состояние выбранного адаптера заново: GUID/индекс, режимы и порядок IPv4/IPv6, активный DoH, текущий журнал. Исходником не назначать старый Xbox/Google по истории переписки.
2. Проверить независимый локальный EXE и аварийное окно --dns-recovery --verify-only. Сверить исходник, адаптер, пользователя/машину, защищённое хранилище. Сохранить доступную без интернета персональную инструкцию. Сейчас автономный путь проверен mock-тестами; его успешная реальная запись ещё не доказана.
3. После отдельного подтверждения сохранить/проверить исходник и применить один согласованный профиль. IPv6, firewall, маршруты, Zapret и TG оставить неизменными. Зафиксировать запись, точный readback DNS/DoH и время.
4. Отдельно проверить HTTPS, затем попросить открыть ChatGPT/Gemini в том же браузере. Не смешивать эти результаты с записью DNS.
5. Для «Применить повторно» использовать точно текущий профиль и DoH, без промежуточного DHCP, очистки кэша и перезапуска служб/адаптера/браузера. Снять состояние до/после; одинаковый readback не доказывает обновление сетевого состояния.
6. Перезапуск браузера и очистка кэша — разные последующие опыты с отдельной фиксацией, не одновременно. Перезагрузка Windows — только по отдельному согласованию.
7. Восстановить исходные режимы, порядок адресов и DoH; проверить точное совпадение. Сценарий ручной → автоматический → исходный ручной выполнить отдельно с тем же защищённым исходником.

Автономное восстановление: локальный production EXE с --dns-recovery, соседний «Восстановление DNS.cmd» и защищённый исходник. Этот вход не создаёт основное окно, не требует GitHub и не запускает инструменты; реальная запись требует подтверждения/UAC. Общая инструкция: docs/DNS_RECOVERY_RU.txt. Отсутствующий/чужой/повреждённый исходник не заменяется сбросом к DHCP. Старые записи разрешаются через существующий сценарий просмотра/согласования, без удаления резервных копий.

## Проект «Хранилище → Очистка старых версий»

На этом этапе это спецификация, не реализованный удаляющий механизм. Никакие версии или пользовательские файлы не удалялись.

Предпросмотр строить по манифестам Config/Modules и Backups с точным перечнем и хешами файлов. Не считать папку старой только по имени или дате. Для каждой версии показать размер, причину включения/исключения и влияние на откат. По умолчанию сохранять активную версию и последнюю пригодную для отката. Неполный старый манифест без полного списка файлов — не кандидат автоматического удаления.

Безусловно исключить внешние пути, текущую версию, используемые процессы, неопределённый статус процесса, текущий откат, DNS-исходники, настройки, журналы, неизвестные/изменённые/добавленные пользовательские файлы, reparse points, неоднозначные hard links, выход за корень и неподтверждённые транзакции установки. Папки из архива разработчика и другие копии приложения не относятся к управляемым версиям этого экземпляра.

Будущий поток: сканирование только для чтения → таблица кандидатов и сохранённых версий → явный выбор → пересчёт хешей и занятости непосредственно перед действием → подтверждение → удаление только согласованного перечня → итоговый отчёт. Если между просмотром и подтверждением что-то изменилось, отменить соответствующий пункт, а не расширять удаление. Открытие раздела, закрытие программы и обновление списка не выполняют очистку. До реализации нужны изолированные тесты активной/старой/неизвестной/изменённой версии, отката, работающего процесса, ссылок и изменения после предпросмотра.
