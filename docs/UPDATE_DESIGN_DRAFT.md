# Open Net updater — проект для согласования

Статус: предложение, обновление в приложении не реализовано. Канал по умолчанию Stable; Pre-release включается только пользователем. Сравнение семантических версий учитывает prerelease и не предлагает даунгрейд alpha до более старой stable. Проверка GitHub Releases только для официального репозитория; отсутствие сети, неподходящие метаданные или отсутствие подходящего пакета дают объяснение и не меняют приложение.

При согласованной установке показывать текущую и новую версии, канал, примечания к выпуску, источник, формат Standard/Portable и необходимость перезапуска. Подтверждение скачивания и установки явно. Выбирать соответствующий архив/EXE строго по метаданным; ограничивать размер и защищаться от ссылок и path traversal. Проверка SHA-256 обнаруживает повреждение, но не устанавливает подлинность, если контрольная сумма пришла по тому же каналу. Нужна отдельная согласованная политика доверия: подпись издателя/проверяемая подпись метаданных, ротация и отзыв ключей; до этого не объявлять пакет доверенным.

Standard: сохранять LocalAppData и модульные каталоги; Portable: оставлять Data/Modules и marker на месте. Отдельный updater с проверенным происхождением и правами не выше необходимых ожидает штатного завершения оболочки, но не сетевых процессов; сохраняет предыдущий EXE до проверенного запуска нового. Передача владения процессами требует отдельного протокола с проверкой PID, времени создания, пути и защищённой записи; неизвестные процессы не останавливаются и не присваиваются. Одна общая область данных и SingleInstance для уже работающей оболочки; разные portable-копии остаются раздельными.

Транзакционный журнал фиксирует проверенный пакет, целевой путь и этап, с безопасным восстановлением после прерывания; проверить реальный успешный запуск и сделать откат при ошибке. Не запускать одновременно два updater; не выполнять неподписанные скрипты; не использовать автоматическое повышение привилегий. Автозапуск проверяется после обновления, без молчаливой перезаписи чужой регистрации. Переименование или перенос установленного пути требует явного восстановления записи пользователем.

Для согласования остаются механизм идентификации доверенного издателя, UX обновления и отката, правила миграции между изолированными каталогами и способ запуска новой оболочки. Тестировать сначала только в изолированных каталогах, с подменой сервера и сбоями: версия, канал, подделка, недоступность, прерванная загрузка и установка, восстановление, сохранение данных и рабочих тестовых процессов. Реальную замену используемого EXE не выполнять без отдельного разрешения.
