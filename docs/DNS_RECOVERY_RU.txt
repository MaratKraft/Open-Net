Open Net 0.4.0-alpha.1 — автономное восстановление DNS

До настоящего испытания сохраните всю папку сборки локально. Интернет для
аварийного окна не нужен. Оно не загружает главное окно, настройки модулей
или GitHub и не запускает Zapret/TG.

1. Запустите «Восстановление DNS.cmd» рядом с EXE.
2. Выберите адаптер с защищённой резервной записью.
3. Сравните текущие и сохранённые исходные адреса, режим и DoH.
4. Нажмите «Восстановить исходный DNS…», подтвердите и разрешите UAC.
5. Программа перечитает настройки и подтвердит результат либо покажет ошибку.

Без защищённой записи кнопка недоступна. Резервная запись создаётся после
подтверждения первой операции и UAC, до изменения DNS. Диагностический JSON
и копия Data/Dns/Backups информативны: они не принимаются как инструкция
привилегированному помощнику. Авторитетный журнал остаётся на этом компьютере:
%ProgramData%\Open Net DNS Recovery\<SID пользователя>.
Перенос Portable на другую машину не переносит право восстановления.

Если обнаружено изменение DNS другой программой, отключён/исчез адаптер,
повреждён журнал или не подтверждена идентичность, автоматическая запись
блокируется. Не удаляйте журнал и не заменяйте его скачанным файлом.
Незавершённая операция может быть восстановлена только при проверяемом
совпадении с сохранённым ожидаемым состоянием или намерением записи.

Если EXE вообще не запускается, используйте свойства выбранного адаптера
Windows и локальную персональную инструкцию из диагностического отчёта:
верните исходный ручной/автоматический режим и порядок адресов, затем
точные сохранённые параметры шифрования (URI DoH и fallback). Не подменяйте
восстановление ручных адресов переключением на DHCP. Не меняйте IPv6,
IP-адрес, шлюз, маршруты или firewall. Это ручное восстановление не заменяет
проверку результатов через DNS Manager после восстановления работы EXE.

«Автоматический DNS» удаляет ручное назначение IPv4 DNS. «Восстановить»
возвращает исходник до первой операции текущей сессии. Это разные действия.
«Применить повторно» сохраняет первый исходник сессии и не очищает кэш.
Если текущий адаптер не имеет своего журнала, чужая/старая запись другого
адаптера не используется. Перед первой подтверждённой записью создаётся
новый исходник текущего адаптера. Сопоставляйте GUID, а не только имя Wi-Fi.

Сборка экспериментальная. Реальные DNS/UAC на Windows 10/11 требуют
отдельного согласованного испытания. Windows не перезагружается автоматически.
